# 用量、费用与报告

[← 文档目录](README.md)

工作台 `#usage` 查看全局或指定会话的用量与费用；QQ 的 `/usage` 和自然语言工具只生成当前会话报告。请求失败率与耗时分析见 [日志与排障](observability.md#请求与稳定性)。

## 记账与额度

记账发生在统一模型网关：chat / vision / draw / image_lab / distill，按通过准入的调用尝试记录。开发者生图使用 `image_lab`，在用量与请求统计中独立显示为「开发者生图」，仍受绘图开关与全局每日额度限制。历史 `draw` + `source: admin` 记录读取时归入此类，不改写账本或重算旧价。一次识图请求失败后再次请求纯文本，会分别记账；图片下载失败而未发出带图请求时，不因此多算一次识图调用。调用前被策略拒绝不计入请求量。记录模型、会话、状态、耗时、可获得的 token、出图数量和错误。

- 每日调用上限包括失败尝试和并发预留，0 代表不限。按 Asia/Shanghai 零点切日。
- token 上限按供应商已经报告的总量阻止后续请求；并发和正在生成的请求可越过阈值，未知 token 无法估算。
- 缺失 usage 明确记为未知。费用是本地估算，实际扣费以供应商账单为准；没有调用与账本读取失败分别展示，后者不会显示为零用量。
- 进程中断后的预留记为 interrupted；无法判断供应商是否已完成/收费，不自动重试。
- WebSocket 心跳时间、收件计数、发送队列/失败数、存储错误、日志写入错误和预算状态可查询；这些是本机观测，不是外部告警服务。

## 费用计价与分享图片

- 新请求在发出前保存供应商、模型档位、价目版本、时段和单价快照。DeepSeek 费用按缓存输入、非缓存输入、输出分别计算，以整数纳元（1 元 = 10 亿纳元）累加；更新内置价目不会重新给旧请求定价。DeepSeek 失败调用若返回完整用量，同样计算预估费用。
- 代码内置价目快照版本为 `deepseek-cny-2026-11-04`（见 [`pricing.js`](../src/usage/pricing.js)），仅对官方 `https://api.deepseek.com`（含 `/v1`）的 Flash / Pro 与已知别名生效。当前实现将北京时间周一至周五 09:00–12:00、14:00–18:00 按高峰估算，其余为空闲；适用窗口为 2026-11-04 至 2026 年末。进入 2027 年后新请求标记费用待确认，需重新核对价目和节假日日历。此处说明代码内置基线，不代表持续核验供应商实时价格。跨时段请求按开始时刻估算，不保证与供应商的计费切分完全一致。[官方价目表](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)
- 绘图价目 `laozhang-images-2026-11-13` 仅匹配 `https://api.laozhang.ai` 与备用域名 `https://api2.laozhang.ai`（含 `/v1`）：GPT Image 2.5 Flare / Sunburst VIP **$0.03 / 次**（¥0.201）；Grok Imagine 2.0 **$0.055 / 返回图片张数**（¥0.3685 / 张）；Nano Banana 2.1 **$0.045 / 次**（¥0.3015）。固定 **1 USD = 6.7 CNY** 估算，尺寸与质量不改变单价，不代表实时汇率、实际充值成本或专属分组倍率。新调用保存美元单价、折算率和人民币单价快照。[供应商价目](https://docs.laozhang.ai/api-capabilities/image-generation-guide)
- 绘图费用不依赖 token usage。GPT 返回图片按次计费，Grok 按返回张数计费；Banana 完整 HTTP 200 响应即按次收费，无图或拦截结果也收费。后续下载、图片超限或本地保存失败不免除已生成费用。明确 HTTP 4xx / 5xx 不计费；超时、断线、响应超限、解析失败或进程中断保持待确认。没有自动重试。Banana 开启搜索时每次检索另收 $0.014，当前没有可靠的检索次数账单字段，整次调用标为费用待确认，避免把生图基础价当成总价。实际扣费以供应商账单为准。[失败计费规则](https://docs.laozhang.ai/en/api-capabilities/image-billing-and-failures) · [Banana 搜索与扣费](https://docs.laozhang.ai/api-capabilities/nano-banana-2-1-image)
- 历史记录缺少价目快照、未配置价目的供应商或模型、DeepSeek 缓存拆分缺失或用量自相矛盾时，费用标为待确认，不纳入已计价总额。原始 token 统计仍保留，不推断未知费用为零，也不用当前配置倒推历史供应商。
- 摘要与走势覆盖全部匹配记录，独立于明细条数；明细中的用途和待确认筛选不改变上方汇总。缓存命中率以有缓存拆分的输入 token 加权，费用环比仅在两段记录都已计价时展示，并比较相同进度。所有统计边界固定为北京时间。
- 每日额度始终为全局口径，显示已报告 token、调用数、进行中的请求和重置时间；账号余额和中转站账单对账尚未接入，页面提供 DeepSeek 开发者平台的账单 / 充值入口。账号余额可能包含其他应用消费，不能倒推为本机器人费用。
- 管理 API `GET /api/usage/dashboard` 返回汇总、趋势、明细及计价依据；`GET /api/usage/report` 返回 PNG。两者均需管理令牌。原 `GET /api/usage` 的账本统计接口保留。
- QQ 可用 `/usage [today|7d|30d]`，或自然语言询问用量 / 费用来调用 `send_usage_report`。群聊报告只读取所在群，私聊报告只读取当前私聊；工具参数不能指定其他会话或全局。分享图片不含账号余额、QQ 号、其他会话和错误原文，网页与图片共用统计逻辑。
- PNG 使用 **Playwright + Chromium** 对用量页面的共享 HTML/CSS 截图，包含费用摘要、计价完整度、走势、缓存命中率与用途分布；不再另行绘制 SVG。工作台与截图共用 `web/usage-view.js` 和现有样式。截图模式隐藏管理操作，并以“当前群聊 / 当前私聊”代替 QQ 号；导航、会话排行、额度与调用明细不进入分享图。
- 网页读取用量时保留最多 32 份、有效期 5 分钟的内存快照；“生成分享图”使用当前快照、内容宽度和视口宽度，不重新查询变化中的账本。预览和下载使用同一份 PNG。快照失效时提示刷新，不悄悄改为新数据。肥鱼 tools 在服务端查询当前会话后调用相同截图器，不依赖管理网站启动或登录。
- Chromium 按需启动并复用，截图串行处理，每次使用独立浏览器上下文，最多接收 4 个处理中 / 等待中的任务；满载返回 429，浏览器不可用返回 503。截图禁用页面脚本和网络请求，只渲染本地模板与统计数据。平台停止时关闭浏览器。
- 截图需要 Chromium 和中文字体；Docker 镜像已包含安装步骤，宿主机安装及 `CHROME_EXECUTABLE` 配置见 [部署文档](napcat-deployment.md#截图浏览器)。
- 发送仅在 OneBot 确认后报告成功，一轮工具调用只尝试发送一次，失败不自动补发。控制台测试只模拟报告，不读取真实账本或发送 QQ 图片。

## 查询范围与开发入口

默认今天，可选近 7 天、近 30 天或自定义日期（最多 366 天）；统计按北京时间。`detailKind` 和 `pendingOnly` 只影响明细，`sessionKey` 影响整页；`limit` 控制明细数量，不截断汇总。

计价在 `src/usage/pricing.js`，统计在 `src/usage/overview.js`，截图与发送在 `src/usage/report.js`；网页与分享图共用 `web/usage-view.js`。账本和准入额度分别由 `src/store/usage-store.js`、`src/platform/usage-policy.js` 管理。

按修改范围选择 `test/usage-dashboard.test.js`、`test/usage-report.test.js`、`test/usage-policy.test.js` 或 `test/usage-store.test.js`；截图测试需要可启动的 Chromium。无需为文档整理执行这些测试。
