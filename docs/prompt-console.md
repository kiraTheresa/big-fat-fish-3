# Prompt 控制台与自然语言工具

管理台的 **Prompt 控制台** 使用一套全局发布配置。现有群聊 / 私聊唤醒条件不变；被唤醒后由模型选择是否调用工具。

## 页面风格

顶部可一键切换“工作台 / 舒展”，默认工作台。工作台使用紧凑分组、细边框和较弱的面板装饰；舒展增加区域留白与阅读行距，保留轻微的玻璃表面。

两个预设共用同一份页面与功能。切换只修改外观属性，不重新载入会话或调用 API，保留未保存的草稿、JSON 临时实验、测试输入、展开项和当前结果。测试运行中仍可切换。浏览器仅保存风格名称，不将外观偏好写入 Prompt 发布配置；本地存储不可用时仍可在当前页面切换。

状态保留已有 DOM 契约回归检查；本次两种风格尚未进行截图视觉验收。可在输入尚未保存的文字后往返切换，检查内容与测试状态，并比较桌面和窄屏的阅读、对齐与点击空间。

## 一次编辑到发布

1. 打开管理台，进入 Prompt 控制台。左侧选择初始人设、群聊 / 私聊规则、记忆提炼、历史与记忆或工具。
2. 修改内容，右侧显示组装预览。展开 system、历史、tools 和筛选明细；“请求 JSON”显示实际请求体的结构。此时不调用模型。
3. 保存草稿。草稿持久化，刷新页面后仍存在；线上仍使用原发布版本。其他页面已修改相同草稿时返回冲突，保留本页未保存内容。
4. 载入全新群聊 / 私聊，或已有会话的快照。快照固定历史、人设、记忆、时间与发言者；测试过程中收到的新 QQ 消息不进入这份快照。快照仅保存在进程内，重启或超过最近 30 份后需要重载。
5. 输入测试消息与预期表现，运行草稿测试；也可以用同一快照依次测试发布版和草稿。每轮是真实模型调用并计入用量。
6. 检查回复、完整调用顺序、工具参数、工具结果和 API 请求。点击“评审通过”或“标记未通过”，可写备注。HTTP 成功不等于效果通过。
7. 检查差异，填写发布说明，点击发布。发布生成不可变版本，后续新请求使用新版本，进行中的调用继续使用已捕获的版本。

测试结果绑定草稿 revision。保存实质改动后，旧测试仍保留，但不能批准新草稿。修改初始人设必须在**全新会话且没有临时替换人设**的场景通过聊天测试；修改提炼提示词必须通过提炼测试。其他聊天 / 上下文 / 工具变化必须通过聊天测试。

临时修改右侧最终请求 JSON 可以做实验，但不能作为发布依据。长期配置使用左侧表单或“配置 JSON”，两者共用一份草稿。实验 JSON 只能使用当前模型及已开启的工具，不能通过增加函数名获得新能力。

版本列表可把旧版本载入草稿，经测试后重新发布。保留最近 50 个配置版本与 50 条测试摘要。

## 人设与记忆的作用范围

- **初始人设**：只用于新建或重置会话。发布不会遍历、替换已有的 `character.md`。现有重置指令原本就同时清空记忆，该行为不变。
- **通用提示词**：身份与消息格式、群聊 / 私聊行为、场景模板、工具使用规则在每轮组装时读取该轮发布配置。
- **会话素材**：群聊共有一份人设与记忆；私聊各自独立。在控制台临时编辑只改变测试素材，不修改正式文件。
- **提炼规则**：编辑后影响后续提炼。默认规则保留当前会话已有的核心设定，不再硬编码另一套性格；不会因初始模板更新而迁移旧人设。
- 场景模板支持 `{{time}}`、`{{scene}}`、`{{silence}}`；提炼模板支持 `{maxBytes}`。未知双花括号变量拒绝保存。

## 历史筛选

最多从最近 1000 条已进入聊天历史的消息中筛选。排除本轮输入和 reset 水位前的内容，再应用时间、角色、发言者、文本 / 图片相关消息与命令筛选，取最近 N 条，最后按预算保留最近连续的一段。N 不包含本轮消息，0 表示不附带历史。

预算是 system + 历史文字的 UTF-8 字节粗算，不包含当前输入、工具定义、图片或协议包装，不等于供应商 Token 上限。system 超过预算时保留 system、舍弃历史，面板显示真实大小。

历史图片仅以文字占位进入上下文；本轮图片理解沿用既有视觉模型路径，可单独关闭。语音、戳一戳等只接收事件不会因筛选设置而自动获得处理能力。

首次启动从已有 `CHAT_CONTEXT_LINES` 和 `behavior.context.budgetBytes` 导入默认值，此后有效值由 Prompt 发布版本管理；旧配置页改为链接到控制台。

## 自然语言工具

| 工具 | 参数 | 执行作用 |
|---|---|---|
| `draw` | `prompt` | 使用现有图片 API，图片进入既有发送队列 |
| `remember_fact` | `content` | 以当前真实发言者的名义保存当前会话的事实 |
| `recall_memory` | 无 | 读取当前会话记忆 |

工具定义随请求的 `tools` 发送，后端验证参数、调用权限与开关，并把 assistant.tool_calls + role:tool 结果完整回传给模型。密钥、用户 ID、会话 ID 不由模型填写。缺少图片 API 配置或绘图功能被停用时，不提供 draw。既有斜杠指令继续使用共享的图片 / 记忆能力。

默认最多 3 轮工具、4 次执行，可在限定范围内编辑。相同副作用调用在一轮对话内复用结果，包含失败结果；工具已执行后发生模型错误不回退重跑。进程重启不重放未完成测试。这不是跨进程、跨入站消息的“恰好一次”投递保证。

## 测试与观察

- 测试消息不发送给 QQ；remember / recall 在隔离的内存副本上读写。
- “模拟绘图”不调用图片 API；“真实绘图”实际调用并计费用量，在控制台展示图片。两种模式下记忆都留在沙盒。
- 提炼测试展示候选人设 / 记忆补丁，校验格式、大小和明确保存的条目，不写入线上文件。
- 测试调用记在用量会话 `p-prompt-test`，沿用原有模型种类与预算。
- 请求、结果、失败和工具过程记录在 `data/prompt-runs/`，最近 50 次运行按条数淘汰，关联测试图片一并清理。运行记录不写入通用日志的全文。
- 控制台请求记录会替换已知密钥、图片 Base64、敏感 URL 参数；长文本超过展示上限会截断，并标记 `redacted`。有省略的 JSON 不能当成逐字完整的请求。
- 保存的草稿和版本位于 `data/management/prompts.json`。管理接口沿用 ADMIN_TOKEN、同源限制；静态页面不包含运行数据。

## 验收场景

| 操作 | 预期与证据 |
|---|---|
| 改历史条数，尚未保存 | 预览立即变化；测试 / 发布不可用；线上请求版本不变 |
| 修改初始人设，保存后刷新 | 草稿保留；已有会话 `character.md` 不变 |
| 全新会话输入“记住我不吃香菜” | trace 出现 remember_fact 参数、tool 结果、第二轮请求；沙盒记忆改变，线上记忆不变 |
| 输入“你会画猫吗”与“画一只猫” | 人工检查模型是否正确区分询问能力和执行请求；真实模型表现需实际验证 |
| 关闭 draw | 预览 tools 不含 draw；后端拒绝模型越权调用 |
| 测试通过后再编辑并保存 | 旧评审不能发布新 revision |
| 评审通过，检查差异后发布 | 发布版本增加；新请求 trace 标注新版本 |
| 选择旧版本载入 | 生成新草稿；线上不立即变化，重新测试后才能发布 |

实现验证使用本地模拟模型 / 图片服务，不代表真实 QQ、模型选择工具的质量或供应商稳定性已通过验收。工具协议参考 [DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)。

## 开发验证

- 回归：`node --test --test-concurrency=1 test/**/*.test.js`。专项用例在 `test/prompt.test.js`，包括模拟上游 HTTP 服务下的请求、工具循环、隔离存储、发布门槛与管理接口。
- 可选浏览器检查：`node scripts/check-prompt-console.mjs`。需要环境中可导入 Playwright；可通过 `PLAYWRIGHT_MODULE` 指定模块文件、`CHROME_EXECUTABLE` 指定浏览器程序。脚本使用临时数据目录、本地模拟模型与临时浏览器资料，验证登录 → 编辑 → 测试 → 评审 → 发布、版本对比、工具预览和手机宽度；结束后清理自己的临时数据。
- 2026-10-27：310 项回归检查通过；上述隔离浏览器流程通过，无页面脚本错误。供应商效果仍由真实测试与人工评审判断。
