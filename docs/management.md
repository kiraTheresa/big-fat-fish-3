# 本地管理与公共服务

[← 文档目录](README.md)

沿用 L1 connection → L2 dispatch → L3 trigger → L4 sender，管理接口不绕过消息发送层，不提供任意脚本执行。

## 启动

1. 使用 Node 22.9+，运行 `npm ci`。
2. `.env` 中保留原有连接与模型配置，增加 `ADMIN_TOKEN`（至少 24 字符随机值）。可用 `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` 生成。
3. 停止旧 Bot 后运行 `npm start`，打开 `http://127.0.0.1:3210`，输入令牌。`npm run dev` 支持源文件重启；更改 `.env` 仍需重新启动。
4. 未设置令牌时只运行 Bot，不开放管理 API。登录成功后，令牌和到期时间保存在当前浏览器的同源 `localStorage` 中，30 分钟内刷新或重新打开工作台可自动验证并进入；刷新不会延长有效期。到期、退出或收到 401 时清除记录并要求重新输入。浏览器禁用存储时仍可登录，但刷新后需重新输入。此期限只控制工作台的登录记忆，不改变服务端 `ADMIN_TOKEN` 的有效期。

`ADMIN_HOST` 默认 `127.0.0.1`，`ADMIN_PORT` 默认 `3210`。Docker 内部监听 `0.0.0.0`，Compose 只把管理端口映射到宿主的 `127.0.0.1`。宿主端口冲突时，可用 `ADMIN_PUBLISH_PORT` 单独指定映射端口。需要远程访问时自行配置 HTTPS 反向代理或 SSH 转发。

使用 Codex 内置浏览器批注时，登录后可在工作台顶部开启「批注兼容」。切换后重新载入页面，启用时仅对本机和局域网直连返回的管理 HTML 放行内联样式。设置作用于当前实例，默认关闭，重启后恢复启动配置；需要启动即开启时可设置 `ADMIN_ANNOTATION_PREVIEW=1`。已有页面需要重新载入才能应用新策略。

同一局域网设备需要访问时，可将 `ADMIN_HOST` 设为宿主机的局域网 IP 后启动，再用该 IP 和管理端口访问。局域网管理仍需令牌，HTTP 直连请在可信网络使用。Compose 部署可将管理端口映射中的宿主绑定地址改为该局域网 IP。批注开关根据实际连接地址判断来源，带转发标头的请求使用默认严格策略。

同一数据目录只允许一个 Bot 进程。2026-10-27 起使用 `proper-lockfile` 维护共享目录中的 `.runtime-lock.lease`：每 5 秒续期，30 秒未续期视为失效；启动最多等待约 35 秒以接管异常退出的旧实例。正常退出立即释放。`.runtime-lock.json` 的 v2 主机名/PID 仅用于诊断，不再跨宿主机或容器判断进程存活，容器重建、PID 复用或运行方式切换不会因此永久卡住。

活跃租约仍会拒绝第二个实例；续期失败/丢失锁的进程会退出，不能继续写数据。接管过程通过短时 `.runtime-lock.acquire` 串行化，防止多个进程同时删除过期租约；该文件在 Bot 开始运行前移除，若进程恰好在接管阶段被强制终止，则需确认没有实例正在启动后备份移走该文件。所有实例使用相同的过期与续期间隔，不支持单独配置。不要手工删除活跃租约；长于 30 秒的进程冻结可能使租约失效。

首次升级遇到无版本号的旧锁或 `.runtime-lock.gate` 时，仍需确认旧进程已停止后备份移走；旧锁没有心跳，不能仅凭“主机不同”猜测已失效。不同数据目录也应使用各自的 `PERSONA_DIR` / `USAGE_DIR`，避免人为共享账本。实现参考：[proper-lockfile](https://github.com/moxystudio/node-proper-lockfile#readme)。

## 工作台设计原则

导航分为「运行」「Bot 管理」「素材」。运行概览集中连接状态、调用数据与常用入口。选中项、主要操作和异常状态使用不同的颜色提示。

Prompt 工作台在顶部提供编辑、保存和「去试聊」。试聊结果、发布检查和运行记录各有对应区域。发布区说明当前草稿缺少哪些测试。紧凑 / 舒适只切换显示密度。窄屏导航横向滚动，编辑与预览按顺序排列。

浏览器检查：`node scripts/check-prompt-console.mjs` 使用临时数据与模拟模型，覆盖草稿到发布和全部页面的桌面 / 手机宽度；可用 `SCREENSHOT_DIR` 保存截图。此检查不代表真实 QQ 或模型效果验收。

### 开发者生图台与模型接入

上游资料核对日期为 2026-11-13。选型时先看模型 ID、接口、参考图能力和尺寸，再查对应模型的参数页。可用模型、分组和价格以老张在线文档及账号控制台为准，本节记录肥鱼的接入约定。[老张图像生成选型指南](https://docs.laozhang.ai/api-capabilities/image-generation-guide) · [Images API 参考](https://docs.laozhang.ai/api-reference/images) · [模型与价格总表](https://docs.laozhang.ai/models)

「素材 → 开发者生图台」（`#image-lab`）使用后端的 `IMAGE_API_BASE_URL` 和 `IMAGE_API_KEY`。浏览器提交表单后，`POST /api/image-lab` 返回任务 ID，后台逐个执行，最多同时保留 5 个进行中或排队的任务。任务复用绘图开关和用量限额。QQ 的 `/draw` 和聊天绘图工具读取 `IMAGE_MODEL`，通过 Images API 文生图。

任务记录保存在 `data/management/image-tasks/`。刷新页面可继续查看状态、请求、用量和作品。进程重启后，未完成任务标为中断，请先核对上游调用记录再提交。历史任务保留参考图文件信息，沿用编辑任务时需重新选择参考图。也可以将已生成的作品直接用作下一轮的参考图。

| 生图台操作 | 发给老张的请求 | 「请求 JSON」显示 |
| --- | --- | --- |
| 文生图 | `POST /v1/images/generations`，JSON 顶层包含 `model`、`prompt` 和已选的可选字段 | 完整请求正文，鉴权与 Content-Type 通过 HTTP 请求头发送 |
| 参考图编辑 | `POST /v1/images/edits`，multipart 上传文字字段和二进制图片。单图用 `image`，多图用重复的 `image[]` | 表单字段预览，附件显示文件名、类型和字节数 |
| Nano Banana 生成或编辑 | `POST /v1beta/models/gemini-nano-banana-2.1:generateContent`，按 Gemini 原生格式发送 JSON | 参考图的 Base64 内容以文件信息代替 |

- GPT Image 2.5 Flare VIP 和 Sunburst VIP 提供宽高、五档质量和透明 PNG。参考图最多 4 张、合计 20 MiB。蒙版能力见官转线路。[GPT Image 2.5 接入文档](https://docs.laozhang.ai/api-capabilities/gpt-image-2-5)
- Grok Imagine 2.0 提供画幅。文生图可设置 1K／2K、两档质量和 1–10 张输出，编辑可上传最多 3 张参考图、合计 20 MiB。[Grok Imagine 2.0 接入文档](https://docs.laozhang.ai/api-capabilities/grok-imagine-image)
- Nano Banana 2.1 提供画幅、1K／2K／4K、思考级别、PNG／JPEG、JPEG 压缩质量、图片或图文输出，以及可单独开启的网页搜索和图片搜索。启用搜索时发送图文输出，实际检索可能额外计费。支持上传最多 14 张参考图，原文件合计限 14 MiB，为 Base64 编码后的请求留出空间。[Nano Banana 2.1 接入文档](https://docs.laozhang.ai/api-capabilities/nano-banana-2-1-image)

参考图使用本地 PNG、JPEG、WebP 文件。生图台请求 Base64 输出，生成的原图自动归入「绘图作品」，任务记录保存作品引用。运行前核对 [Clash / Mihomo 分流](napcat-deployment.md#使用-clash--mihomo-分流)。

令牌分组决定可调用的模型，模型 ID 选定本次请求的模型。接口和参数兼容时可复用现有请求格式，例如 Flare VIP 和 Sunburst VIP 可以在同一类请求里替换 `model`。对于同样标为 Images 的其他型号，也要核对尺寸、质量和附件字段。比如 FLUX.2 和 Seedream 的参考图编辑走 `/v1/images/generations`，参考图放在各自的 JSON 字段里。Nano Banana 可走 Chat Completions 或 Gemini 原生协议，需按所选协议组装请求和解析响应。[老张图像生成选型指南](https://docs.laozhang.ai/api-capabilities/image-generation-guide)

扩展模型时按目标模型确认生成和编辑各自的路径、请求字段、文件格式、响应结构及计费方式，再据此决定工作台开放哪些参数。项目已有绘图价目及适用范围见 [用量、费用与报告](usage-monitoring.md#费用计价与分享图片)。

## 配置优先级与生效

- 启动配置优先级：已有进程环境变量 > `.env` > `src/config.js` 默认值。Node 的 env-file 不覆盖已有环境变量。
- 行为初值：`config.json` 覆盖代码默认值。
- 首次在面板保存后：`data/management/settings.json` 的行为和策略优先；后续修改 `config.json` 不会覆盖面板已保存的配置。
- 面板保存先校验、原子落盘，再更新内存，对后续请求立即生效；不会取消正在进行的请求。
- 连接、模型名称、密钥、存储路径与端口仍由 `.env` 管理，需重启；面板只显示非密钥信息和“是否已配置”。
- 每次保存需要原 revision，其他页面抢先保存会返回 409，避免覆盖他人修改。
- 管理状态文件损坏时启动报错，保留原文件；不会静默重建权限或预算。

## 权限

默认所有 QQ 都能使用绘图，群聊仍须 @ 本鱼。后台角色：

- `user`：普通用户，使用已启用的能力；私聊中可管理自己的会话。
- `admin`：同时可执行群会话管理指令（reset、history、persona reset）。
- `blocked`：事件仍接收并存入收件箱，完全不进入触发器或聊天上下文。

`ADMIN_QQ` 继续作为管理员初值。仅在后台明确保存的角色覆盖它；自动登记用户不会把环境权限固化。恢复默认会移除后台覆盖，因此 `.env` 中的管理员仍是管理员。QQ 管理员身份不自动赋予网站访问权限，网站使用独立令牌。

## 接收边界

完整列表与官方依据见 [OneBot 接收契约](onebot-reception.md)。标准消息段、message/notice/request/meta_event 和未知扩展均可收件，支持数组与 CQ 字符串。语音、视频、文件及其他不支持的段只保存，不下载附件、不批准请求、不自动回复；含这些段的混合消息也只入收件箱。`face` / `mface` 已支持表情收藏与发送，戳机器人通知可触发短回复，具体资格见接收契约。

## 持久化

| 路径 | 内容 |
|---|---|
| `data/events/YYYY-MM-DD.jsonl` | 按 UTC 日期的原始事件收件箱 |
| `data/logs/YYYY-MM-DD.jsonl` | 按 UTC 日期的脱敏结构化日志 |
| `data/management/settings.json` | 行为配置、功能开关、预算与 revision |
| `data/management/users.json` | 用户身份、显式角色、备注与最近出现时间 |
| `data/management/prompts.json` | Prompt 发布版本、草稿和测试评审摘要 |
| `data/prompt-runs/` | 最近 50 次运行的脱敏请求与测试结果、关联测试图片 |
| `data/media/generated/` | 绘图原图及提示词、模型、会话等元数据，长期保留 |
| `data/media/meme-library.json` | 共享收藏索引、名称、状态与使用记录；旧版迁移备份位于同目录 |
| `data/media/memes/` | 表情类型、发送参数、名称与标签，以及可选原图/预览，长期保留；见 [媒体文件存储](media-storage.md) |
| `data/management/jobs.json` | 任务定义、下一次时间、上次结果 |
| `data/messages/*.jsonl` | 既有可处理消息及出站文本；保留归一化消息段 |
| `data/session-state/*.json` | reset / distill 水位 |
| `data/personas/*/` | 人设、记忆与修改历史 |
| `data/usage/*.jsonl` | 每次模型 API 尝试的账本 |
| `data/usage/.pending.json` | 已预留但尚未记账的调用 |

新 JSON 文件采用同目录临时文件写入、fsync、rename 原子替换；JSONL 按文件串行追加；关键管理文件新建权限为 0600。按各存储模块兼容旧数据；共享表情索引会自动备份并从 v1 迁移为 v2，详见媒体存储说明。各存储库仍保留自己的业务串行化，避免读改写丢失。

单文件替换不代表跨文件事务；正常信号停机先停止接收并尝试等待正在处理的事件/出站队列，最多 8 秒；超时会退出，未完成模型调用靠预留账本恢复为中断。出站队列仍在内存中，历史中的 bot 行表示准备发送，不保证 QQ 已送达。备份应停止 Bot 后复制完整数据目录与配置；不要只复制部分账本或任务状态。

## 调度语义

任务类型限制为：`distill`（按原有条件扫描并提炼记忆）与 `maintenance`（删除过期观察日志/事件）。没有新增任何 QQ 主动发送场景。

- 支持间隔及一次性时间，启停、修改和删除；内置数据维护默认每 6 小时执行，记忆提炼默认每 5 分钟扫描（`DISTILL_INTERVAL_MS=300000`）。维护只清理超过保留期的日志和事件，不改变默认 30 天保留期。
- 启动时，未经手动修改的旧内置任务会从 1 分钟扫描 / 24 小时维护迁移到新间隔，并从启动时重新计时；管理台创建或修改过的任务保留原设置。已有 `.env` 显式配置仍优先，需同步调整 `DISTILL_INTERVAL_MS`。
- 同一时间只执行一个任务，按到期时间选择；执行期间不能修改/删除该任务。
- 开始执行前持久化领取状态；间隔任务结束后再排下个周期，错过的周期不补跑。
- 一次性任务即使失败也停用。进程中断后记 `interrupted`，不重放该次任务。
- `distill` 自身仍有会话防重入/退避；关闭功能开关或缺少 Key 时扫描不会调用模型。

### 群聊记忆提炼休眠

- 默认最后一次有效调用后 2 小时休眠，配置项 `DISTILL_IDLE_MS=7200000`。正常受理的聊天（已启用的 @ / 喊名 / 引用回复 / 戳一戳）、有效绘图、已知且有权限的指令、`ping` 都会激活或续期；普通闲聊、空聊天、冷却中跳过的聊天、未 @ 的群指令、未知指令和权限拒绝不会续期。
- 活跃群仍按每 5 分钟扫描，待处理消息满 50 条或聊天安静 10 分钟时提炼。两小时时限之后的闲聊立即排除；下一轮扫描最多做一次收尾，然后从活跃扫描集合移除。收尾也遵守功能开关、用量限制和失败退避。
- 休眠群继续接收事件和保留聊天历史，但不周期读取聊天文件或调用提炼模型。再次有效调用立即恢复回复与记忆积累，无需手动开关，也不等待下一轮扫描。
- 活跃时间段、最后调用时间和提炼进度保存在 `data/session-state/*.json`。启动恢复活跃集合；休眠前失败或剩余未处理内容保留到下次唤醒，休眠期间的闲聊不补提炼。收尾开始前先持久化休眠，崩溃或失败不会导致后台反复重试。
- 群聊按本地接收时间筛选活跃窗口，每次最多处理最早的 100 条待处理消息，成功后推进进度；同毫秒不同消息分别去重。首次升级没有活跃记录的旧群默认等待下一次有效调用，不自动回填旧历史。已有长期记忆保留，私聊提炼逻辑不变。
- 此策略只影响长期记忆提炼。普通聊天回复继续沿用已有的短期上下文配置；没有新增“唤醒时补读并提炼闲聊”的行为。
- `RETENTION_DAYS` 默认 30；清理只删除命名符合规则的旧日志/事件文件，保留消息、人设、角色、任务及用量账本。

## 戳一戳与对话冷却

- 配置中心可开关 `trigger.poke.enabled`，编辑 `trigger.poke.prompt`。群聊与私聊仅响应其他用户戳机器人，戳别人和机器人自己的通知只记录。
- 戳一戳结合当前人设、记忆与对话历史生成一句短回复，跳过图片识别、工具和随机回复延迟，不分段、不引用通知；使用文字对话的能力开关和额度。
- `chat.cooldownMs` 默认 2000 毫秒。聊天和戳一戳按会话共用，从开始响应计时，窗口内后续触发静默跳过；随机回复延迟仍是另一项设置。
- 首次配置可用 `CHAT_COOLDOWN_MS` 指定冷却，`config.json` 同名行为字段覆盖环境初值；面板保存后以面板为准。旧管理配置启动时自动补齐新增字段，下次保存时持久化。
