# 肥鱼 Prompt Studio · 前端验证原型

日期：2026-11-04。状态：交互原型，等待使用反馈；不是已选定的产品设计，也不是业务验收结果。

**最新原型为 [V4：角色与上下文工作台](v4/README.md)**，预览地址为 <http://localhost:4173/v4/>。[V3](v3/README.md) 与 [V2](v2/README.md) 保留供比较。下文保留 V1 的设计和验证记录，便于比较，不代表已选定 V1 方向。

## 打开

在仓库根目录运行：

```sh
python3 -m http.server 4173 --bind 127.0.0.1 --directory demos/prompt-studio
```

打开 <http://127.0.0.1:4173>。不启动 Bot，不读取 `.env`、运行数据或线上 Prompt，不调用外部服务。已有产品代码保持原状。无新增依赖、编译或安装步骤。

草稿使用当前来源下的浏览器 localStorage，键为 `fish.prompt-studio.demo.v1`。修改后自动保存，快捷键保存会立即写入。存储不可用或旧草稿无法读取时，页面保留原存储、显示提示，并允许导出当前草稿。不要把这里当作正式备份或密钥编辑器。

## 业务取舍

主任务是：**选择一个场景，组合上下文，专注修改一段 Prompt，随时检查本轮材料。**

现有 `web/prompt.js` 提供约十个编辑入口，并在同一长页面铺开素材、编辑、请求、测试、评审、发布和运行记录；`web/app.js` 的管理导航还有约十一个页面。此处的现状判断来自源码结构，不代表完成了旧界面的独立视觉评审。

| 用户任务 | 原型处理 | 收起的复杂度 |
| --- | --- | --- |
| 找到要改的主体 | 中间只有当前积木的正文；左侧显示分类和一句用途 | 不同时展开全部表单 |
| 拼接已有材料 | 积木库添加、角色/回应方式替换、拖动或按钮排序、启停 | 不做自由画布、任意连线、任意嵌套 |
| 复用自己的内容 | 当前积木存入库，在另一个空间加入独立副本 | 不引入共享引用与级联更新 |
| 持续修改 | 编辑/阅读、专注模式、本地自动保存；切换积木保留文本和编辑位置 | 不为外观切换重新请求后端 |
| 看见材料去向 | 底部常驻概览；按需展开完整组装、启用工具和历史裁剪 | 不把请求 JSON 常驻在编辑器旁 |
| 检查改动 | 每空间一份手动快照，比较只展开变化；恢复前说明影响 | 不在原型中仿造正式发布成功 |
| 试一次对话 | 常驻测试区、固定场景、自定义输入、捕获本次上下文 | 不把预设回复当作模型效果 |
| 记录体验 | 本地体验反馈，随草稿 JSON 导出 | 不自动发送给任何人 |

### 页面安排

- **工作空间**是唯一日常主页面：上下文拼图 / 当前编辑 / 试聊。桌面三栏；中等宽度保留拼图，编辑与试聊切换；手机将积木缩成横向列表，保留同一份编辑状态。
- **积木库**是按需打开的面板：查找、加入、替换、保存当前积木。
- **上下文预览**和**快照比较**是按需打开的面板，不跳走主任务。
- **设计说明**保存业务取舍、原型边界与路线。
- 运行日志、用量、权限、调度等继续属于正式产品的运维区域，后续统一外观，当前不复制进原型。

### 视觉方向

采用浅色编辑工作台、低饱和绿作为少量强调、清晰的正文层级与细边框。编辑区拥有最大空间，类别色仅用于小标签与预算示意。使用系统字体与一致的线性 SVG，不使用外部字体和图片。

ui-ux-pro-max 的检索提供了通用布局、可访问性和交互参考；两次设计系统检索的落地页结构均不适合编辑工作台，未套用或保存为设计规范。当前三栏布局和浅色方向是结合任务所作的设计判断，需由原型体验验证。

## 可以体验的路径

1. 修改“大肥鱼”正文，切换到别的积木再回来，刷新检查内容仍在。
2. 存为快照，再改一句话，比较快照；恢复前可先导出草稿。
3. 打开积木库，搜索“傲娇猫”，替换当前人设；其他积木保留。
4. 将编辑后的积木存入库，切到“雨夜猫咖”，从库里复用；两个空间的后续修改独立。
5. 上下移动积木，或拖动排序；打开“查看组装”检查顺序。
6. 停用“相关记忆”，检查启用数与组装变化。固定边界必须保持启用。
7. 将示例预算降到 512，检查历史裁剪与仍然超限时的提示；不会偷偷截断固定正文。
8. 选择验证场景或输入自定义消息，模拟一次；查看本次材料，再修改正文，检查旧记录提示已过时。
9. 在较窄窗口中切换编辑/试聊；专注编辑后退出，检查内容和编辑位置。
10. 移除积木时，可以先存入库再移除；固定规则不可移除。

## 原型边界

- 积木是当前空间内的独立副本。固定边界必须存在且启用；人设和回应方式在库中选择时替换同类积木。
- 角色库是演示数据；替换人设只改变原型配置，不代表真实 Bot 已支持多人格。
- 记忆是虚构、可编辑的示例素材，不做真实相关性检索、事实写入或迁移。
- 所有对话输出是场景预设，自定义输入只返回原型说明。更改 Prompt 不会触发真实生成，不能从预设回复判断效果改善。
- token 使用混合文本粗估，工具按固定占位估算。8,000 仅是界面示例，不是已验证的产品默认值；未计图片、协议、输出和工具多轮增长。
- 原型仅对历史按整行裁剪；其他材料超限时明确提示。完整的分区预算、真实 tokenizer 和供应商限制留到后端接入阶段。
- 本地快照保留最近一份；导出为原型 JSON，不可直接导入正式 Prompt 发布配置。
- 不新增部署、发布、真实模型费用或真实 QQ 操作。

## 阶段路线与每轮循环

用户已将路线调整为**前端所见先行**。先看完整可操作样稿，再让后端结构支持被验证过的业务。

原型循环：**明确本轮体验 → 做出可看可操作的样稿 → 用户反馈 → 调整。** 不默认跑测试或完整浏览器验证；正式实现按风险和阶段选择必要检查。 技术通过、视觉接受和模型行为评审分别记录，不互相替代。

| 阶段 | 交付范围 | 进入下一阶段的依据 |
| --- | --- | --- |
| 01 · 前端原型 | 当前工作台、真实可编辑状态、业务取舍、交互证据 | 用户能围绕主任务找到主体；解决影响使用的布局与导航问题；视觉方向得到反馈 |
| 02 · 人设与会话状态 | 依据原型定义角色、选择与退出、临时状态、权限和持久化作用范围 | 切换与退出可解释；保留用户事实；并发与旧会话行为有明确约定 |
| 03 · 真实上下文 | 沿用 `src/prompt/builder.js` 和测试沙盒，接入来源、选择和真实预算观察 | 同一快照可复现；裁剪可解释；token 计量及回复/工具余量覆盖实际模型 |
| 04 · 记忆与表情 | 事实主体/来源/纠正、提炼与人格变化分开；场景化表情策略 | 同一组场景下评审真实模型表现；角色剧情不写入现实事实 |
| 05 · 正式前端与迁移 | 接现有草稿、评审、发布；旧数据保护、回退；整理其余管理页面 | 定向自动化与页面流程通过；迁移可回退；模型与用户体验评审单列 |

不提前做向量数据库、自动人格调度、任意布局编辑器、多代理规划、完整前端框架迁移。出现现有方案无法满足的具体场景再引入。
